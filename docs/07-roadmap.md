# 07. 로드맵 — 단계, 마일스톤, 리스크

기간은 **개발자 1~2명** 기준 추정이다. 규칙 정확성이 신뢰의 전부이므로, 게임 수보다 각 게임의 완성도를 우선한다.

## Phase 0 — 기반 (2~3주)

목표: **오목 한 판을 링크 초대로 끝까지 둘 수 있다.** 이 한 줄이 되면 나머지 게임은 "모듈 추가"다.

- [ ] 모노레포 셋업 (pnpm, Turborepo, 공유 tsconfig/eslint, CI)
- [ ] `game-core`: GameDefinition, Rng, MatchRunner, Clock, 공통 속성 테스트 헬퍼
- [ ] `games/omok` 규칙 + 테스트 + 표기
- [ ] `ui`: 디자인 토큰, 라이트/다크, Button/Card/Dialog/Sheet, 보드 프리미티브, `useBoardInput`
- [ ] `apps/web`: 홈(정적 카드) → 게임 상세 → 대국 화면 뼈대, 같은 기기 2인 오목
- [ ] `apps/realtime`: RoomManager, GameSession, 링크 초대, 재접속, 시계
- [ ] `protocol` 스키마, 서버 통합 테스트 1개, Playwright E2E 1개
- [ ] 게스트 세션(서명 쿠키), Postgres 스키마, 수 기록 저장
- [ ] `pnpm gen:game` 스캐폴드 스크립트
- [ ] 배포: Vercel + Fly.io + Neon + Upstash 프리뷰/프로덕션

마일스톤 **M0**: 두 사람이 서로 다른 기기(모바일 브라우저 포함)에서 오목을 끝까지 두고 리플레이를 본다.

## Phase 1 — MVP 8종 (8~10주)

게임은 구현 난이도 순으로. 각 게임은 규칙 PR → UI PR → AI PR.

| 주차 | 게임 | 새로 생기는 인프라 |
|---|---|---|
| 1 | 고누 | 그래프형 판 프리미티브 |
| 2 | 체커 | 강제 잡기·복합 수(경로) 모델, 드래그 입력 |
| 3 | 만칼라 | 가로형 판, 순차 애니메이션 |
| 4~5 | 체스 | perft 테스트, 승격 UI, SAN/FEN |
| 6~7 | 장기 | 교차점 판·궁성, 배치 선택 수, 한자 폰트 |
| 8 | 윷놀이 | 난수 수(`throw`), 다중 말, 이동 큐 UI, 초읽기 시계 |
| 9~10 | 바둑 | 협상 phase(사석 합의), 면적 계가, 9/13/19 옵션 |

병행 작업:
- AI 레벨 1·2 (Web Worker)
- 랜덤 매칭 큐 + Glicko-2 레이팅
- 계정(이메일 매직링크 + Google) + 게스트 승계
- 프로필(게임별 레이팅 칩), 결과/리플레이 공유 링크
- 규칙 배우기 페이지 8종 (30초 요약 + 인터랙티브 연습)
- 정형 메시지, 무승부 제안·재대국
- Sentry/PostHog, 퍼널 계측

마일스톤 **M1 (MVP 공개)**: 8종 모두 DoD 통과, 초대 링크 전환율·완주율 측정 시작.

## Phase 2 — 플랫폼화 (MVP 후 8~12주)

- 친구 목록·초대, 관전(읽기 전용 소켓 룸), 대국 중 자유 채팅(신고·차단 포함)
- 강한 AI: KataGo(바둑, MIT) 검토, 체스·장기는 GPL 엔진 분리 프로세스 방식 법률 검토 후 결정
- 바둑 한국식 집 계가, 오목 렌주 금수, 장기 점수제, 체커 10×10, 만칼라 오와레
- 신규 게임: 샹치, 쇼기, 백개먼, 나인 멘스 모리스, 리버시(명칭 확인 후)
- PWA(설치, 오프라인 AI 대국·학습 페이지), 푸시 알림(내 차례)
- 데일리 퍼즐/오늘의 게임, 클럽(가벼운 그룹) 초기 버전
- 다중 realtime 인스턴스 (Redis adapter)

## Phase 3 — 확장 (이후)

- 모바일 앱: Capacitor로 웹 래핑 → 스토어 배포. 네이티브 필요 기능(푸시·결제)만 플러그인
- 토너먼트(스위스), 시즌 랭킹, 국가·지역 리더보드
- World Board Games: 지도에서 나라별 전통 게임 발견
- 자체 오리지널 게임 트랙 (`06` §7 가이드)
- 라이선스 게임 협상
- 수익화 검토: 광고 없는 프리미엄(보드 스킨, 무제한 분석), 절대 사행성 없음

## 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 규칙 버그(특히 체스 앙파상/캐슬링, 바둑 계가, 윷 지름길) | 신뢰 상실 | perft·픽스처·속성 테스트 필수. 출시 전 각 게임 유경험자 10판 테스트 |
| 모바일 브라우저 소켓 끊김 | 대국 중단 | 재접속 1급 기능, 서버 룸 유지, 시계는 서버 기준 |
| 바둑 사석 합의 분쟁 | 무한 대치 | 불일치 시 재개 → 재패스 → 그래도 불일치면 면적 계가 자동(모든 돌 살아있다고 가정) 옵션 |
| 실시간 서버 단일 인스턴스 장애 | 전체 다운 | Fly.io 자동 재시작, 룸 스냅샷 Redis, 재접속 시 복원. Phase 2에서 다중화 |
| GPL 엔진 연동 | 라이선스 의무 | MVP 미사용, Phase 2 법률 검토 후 분리 프로세스 |
| 명칭 상표 문제 | 리브랜딩 비용 | 서비스명·게임명 KIPRIS/USPTO 사전 검색 |
| 범위 과대 | 출시 지연 | 8종 외 요청은 Phase 2 백로그로. M0 전에는 오목 외 게임 착수 금지 |
